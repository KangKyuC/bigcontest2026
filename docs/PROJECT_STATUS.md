## 다음 검증의 입력·출력

정책 담당자는 사업·회차·기능·자격·신청기간·제공기간·제공지역·운영시간·채널·공식 원문을 정리합니다. 모델 담당자는 집계 관측·품질·기간·반례를 전달합니다. 가상의 정책 검증 시나리오라는 사실과 실제로 관측한 집계 특성을 구분합니다.

판정은 다음 네 층으로 나눕니다.

1. 개별 조건: 충족·불충족·추가 심사·정보 미확인.
2. 사업·회차: 기능 적합성·충돌·미확인 조건을 함께 보존.
3. 같은 지원 필요의 전체 경로: 다른 사업·대안·예외를 비교.
4. 근거·조치: 기존 경로 안내·조건 보완·추가 조사·판정 보류.

한 사업에 시간 충돌이 있어도 다른 사업이 조건부 후보일 수 있습니다. 제약·대안·정보 부족을 배타적인 고립 위험 등급 하나로 합치지 않습니다.

## 가장 작은 공동 실험

같은 2~3개 사례에서 아래 표를 채웁니다. 새로운 정책을 많이 모으거나 대시보드를 넓히는 작업보다 먼저 수행합니다.

| 정보 조건 | 추가 정보 | 기록할 결과 |
| --- | --- | --- |
| B0 | 정책·인구·주민조사·필요한 시설정보 | 활동자료 없는 기준 판단 |
| B1 | + 공개 연락·외출 특성 | 기술통계만으로 새로 확인한 질문·반례 |
| B2 | + 대회 SK 장소 유동 | 제공 데이터 때문에 바뀐 조사·해석 |
| B3 | + 학습 모델 | 단순 비교위치 이상으로 개선된 판단 |

모든 조건에서 정책 자격은 동일하게 유지합니다. 개선 판정에는 공식 근거, 반례, 추가 조사가 필요한 이유를 붙입니다. 연결이 실패하면 데이터가 도움 되지 않은 사례로 보존합니다. B3가 B1·B2를 개선하지 못하면 학습 모형을 서비스의 필수 판단엔진이라고 주장하지 않습니다.

## 대회에서 설명할 것

제공 SK 활용과 모델 개발·평가·재현 코드는 구체적으로 제시할 수 있습니다. 그러나 활동 특성의 밀도·유형화를 사회적 고립 위험 예측으로 바꿔 말할 수 없습니다. 주제설명서의 위험 예측·분류 최소 성과물과 남은 간극을 명시하고, 지원경로 검토의 실제 사례가 그 목적에 어떤 기여를 하는지 검증해야 합니다.

정책 공백·위험주민 수·지원 참여 증가·고립 감소 효과를 아직 확보한 성과로 적지 않습니다. 이 저장소의 의도는 평가 가능한 성과와 미검증 가설을 분명히 구분해 다음 작업을 시작할 수 있게 하는 것입니다.
